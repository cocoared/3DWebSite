# 用語集（3D ポートフォリオサイト）

このプロジェクトで登場する専門用語を、できるだけ日常の言葉でまとめた辞書です。
「コードのコメントに出てくるあの単語、結局なに？」を引くために使ってください。

---

## 1. Web / React まわり

### イミュータブル（immutable / 不変）

**「一度作ったオブジェクトを書き換えず、変更したいときは“新しいコピー”を作る」** という考え方。

- 悪い例（ミューテーション＝直接書き換え）
  ```ts
  user.name = "新しい名前"; // 元のオブジェクトを壊してしまう
  ```
- 良い例（イミュータブル＝新しく作る）
  ```ts
  const next = { ...user, name: "新しい名前" }; // 元はそのまま、別物を作る
  ```

なぜ大事か：元の値が勝手に変わらないので、**バグの原因を追いやすく**、React が「変わった／変わっていない」を正しく判定できます。
このサイトでは [`PortfolioExperience.tsx`](../components/PortfolioExperience.tsx) の `setParam` が典型例で、`{ ...prev }` で新しい状態オブジェクトを作っています。

> 補足：毎フレーム動くアニメーションの内部値（`useRef` に持つ回転角など）は、性能のため“あえて”書き換えます。イミュータブルにするのは主に **React の状態（state）** の話です。

### ref（useRef）

**「再描画を起こさずに値を持っておく箱」**。
`useState` は値を変えると画面が再描画されますが、`useRef` は `.current` を書き換えても再描画されません。
毎フレーム更新する回転角やドラッグ量など、「画面の再描画とは無関係にこっそり持ち回りたい値」に使います。

### useMemo

**「重い計算を初回だけ実行して、結果を覚えておく」** フック。
3D のメッシュやマテリアルは作るのが重いので、`useMemo(() => build(), [])` で **一度だけ組み立て**、以降は使い回します。

### useFrame（React Three Fiber）

**「毎フレーム（1 秒に約 60 回）呼ばれる関数」** を登録するフック。
ここで時間を進めたり、スライダーの値をシェーダーに渡したり、炎の形を計算したりします。ゲームの「毎コマの更新処理」だと思ってください。

### フォーカス（focus）とフォーカス管理

**「キーボードの操作がいま届く場所」**。Tab キーで移り、Enter やスペースでその部品を押せます。
フォーカスのある部品が画面から消えると、フォーカスはページの先頭（`<body>`）に落ち、キーボードで操作している人は **どこにいたかを見失います**。
そこで THE JEWELS では、月のラベルを押して石を選ぶと（押したラベルは隠れるので）**解説カードの見出しへ** フォーカスを移し、カードを × や Esc で閉じるときは、カードの中にフォーカスがあれば **選んでいた月のラベルへ** 返しています。ラベルは見えるようになるまでフォーカスできず、閉じた直後はカメラが石に寄ったままでラベルが画面の外にあるので、閉じる前に「この月へ返す」と約束だけしておき、カメラが戻ってラベルが見えた瞬間に移します（約束は 3 秒で期限切れ）（[`lib/monthLabels.ts`](../lib/monthLabels.ts) の `requestLabelFocus` と `placeMonthLabel`）。
キーボードで選んだときだけ出る枠（`:focus-visible`）も、「いまどこにいるか」を目で見て伝えるための大事な印です。
ボタンではない要素（見出しなど）にフォーカスを移したいときは `tabIndex={-1}` を付けます。**Tab キーでは止まらないが、プログラムから `focus()` で当てられる** 状態になります。エラー画面（[`app/error.tsx`](../app/error.tsx)）では、画面が出たときに見出しへフォーカスを移しています。

### ライブリージョン（role="status" / aria-live）

**「中身が替わったときに、スクリーンリーダー（画面の読み上げソフト）が自動で読み上げる場所」**。
`role="status"` を付けた要素の文が替わると、今読んでいる内容を邪魔しないタイミングで読み上げられます。
こつは 2 つあります。

- **替わるたびに読み上げるので、長い文や何度も替わる数字には付けない。** このサイトでは見出し全体ではなく「浜辺のシーンを表示しています。」のような短い文だけを読み上げ用の場所に入れています。
- **読み上げ用の場所は先に置いておき、あとから文を入れる。** 作られたときから入っている文は、読み上げられないことが多いためです。このサイトの知らせ（[`PortfolioExperience`](../components/PortfolioExperience.tsx) の `role="status"`）もいつも置いておき、石を選んだとき・解説カードの前後の月のボタンで移ったときに「5月の誕生石、エメラルドを表示しています。」のように中の文だけを替えています。

### ランドマーク（`<main>` / `<nav>` / `<header>`）

**「ページの中の大きな区画に付ける、読み上げ用の目印」**。スクリーンリーダーには区画の一覧から飛ぶ機能があり、`<main>`（本文）・`<nav>`（ナビゲーション）・`<header>`（ページ全体の見出し部分）などの要素がその行き先になります（`<header>` は `<main>` の中に置くと目印にならず、ただの区切りになります）。
見た目は `<div>` と変わりませんが、`<div>` だけで組むと目印がなく、読み上げで使う人は頭から順にたどるしかありません。
このサイトでは、全画面の外枠を `<main>` にし（[`PortfolioExperience`](../components/PortfolioExperience.tsx)）、シーンのタブと月のラベルは `aria-label` で名前を付けた `<nav>` にしています（誕生石シーンでは `<nav>` が 2 つ並び、名前がないと区別できないため）。このサイトの目印は `<main>` と `<nav>` です。

### シート（ボトムシート）

**「画面の下から出てくる、幅いっぱいのパネル」**。スマホのアプリでよく使われる形です。
このサイトでは、スマホ向けの配置（下の「ブレークポイント」の `compact:`）で石を選ぶと、解説カード（名前・石言葉・説明・特徴）がシートとして画面の下に出ます（高さは最大で画面の 45%、中身はシートの中でスクロール）。上の空いたところには 3D の石が見えます。

### 開閉ボタン（aria-expanded / aria-controls）

押すたびに中身を出したり隠したりするボタン（ディスクロージャー）。見た目の三角だけでは、読み上げソフトを使う人に「開いているか」が伝わらないので、属性で知らせます。

- `aria-expanded`：いま開いているか（`true` / `false`）。読み上げソフトは「折りたたみ」「展開」のように読みます。
- `aria-controls`：このボタンが開け閉めする場所の `id`。

スマホ向けの配置の操作パネルの「Environment」ボタン（[`ControlPanel`](../components/ui/ControlPanel.tsx)）と、解説カードの「▸ 特徴」ボタン（[`JewelCard`](../components/ui/JewelCard.tsx)）で使っています。閉じている中身は `hidden`（`display: none`）にして、読み上げやキーボードの移動からも外します。

### ブレークポイントとスマホ向けの配置

**「この幅を境に、画面の配置を切り替える」** という境目の幅。Tailwind では `md:` を付けたクラスが「幅 768px 以上のときだけ効く」指定になります。
ただ幅だけで切り替えると、スマホの横持ち（例: 844 × 390）は幅が 768px を超えるのでパソコン向けになり、高さが足りずにパネルが潰れます。
そこでこのサイトでは、[`app/globals.css`](../app/globals.css) に **独自の条件（カスタムバリアント）** を 5 つ定義して、`md:` の代わりに使っています。

- `compact:`：スマホ向けの配置。幅が 768px 未満、**または** 高さが 480px 以下。
- `roomy:`：パソコン向けの配置。`compact:` のちょうど反対。
- `short:`：高さが 480px 以下（横持ちなどで、さらに詰めて表示する）。
- `tiny:`：高さが 256px 未満（400% に拡大したときなど）。中身が入りきらないので、UI の層ごとスクロールさせる。
- `small:`：幅か高さが 360px 未満。配置は切り替えず、誕生石の月のラベルを小さくするだけに使う（文字盤が小さく写り、隣のラベルと重なるため）。

例えば見出しは `text-[44px] short:text-[28px] roomy:text-[76px]`（スマホは 44px、横持ちは 28px、パソコンは 76px）。
3D 側で同じ条件を使うときは [`lib/scene.ts`](../lib/scene.ts) の `isCompactLayout`（`ROOMY_MIN_WIDTH_PX` = 768 と `COMPACT_MAX_HEIGHT_PX` = 480）を使います。CSS と値が食い違うとシートと石が重なるので、`lib/scene.test.ts` が CSS を読んで `compact:` / `roomy:` / `short:` の値を照らし合わせています（`tiny:` と `small:` は 3D 側で使わないので照らし合わせません）。

注意が 2 つあります。

- **クラス名は組み立てずに、そのままの文字列で書く。** Tailwind はソースの文字列を読んで、見つけたクラスだけを CSS にします。`` `${"short"}:sr-only` `` のように組み立てると、`short:sr-only` の CSS が作られず、黙って効きません（実際に起きました）。
- **同じ性質を上書きするときは、定義の順が効く。** 独自の条件の CSS は `app/globals.css` に書いた順に並ぶので、`compact:pt-4.5 short:pt-2` では後に書いた `short:` が勝ちます。定義の順を入れ替えると上書きが逆になります。

### sr-only（見た目だけ隠す）

画面には出さず、**読み上げソフトには読ませる** ためのクラス（Tailwind の `sr-only`）。要素を 1px の大きさに縮めて切り抜きます。
`hidden`（`display: none`）は読み上げからも消えるのに対して、`sr-only` は中身が残ります。

このサイトでは、狭い・低い画面で見出しの説明文と操作のヒントを `sr-only` にしています（[`SceneHero`](../components/ui/SceneHero.tsx)）。3D を広く見せつつ、読み上げソフトを使う人には石言葉などの説明を届けるためです。

### visibility: hidden と display: none

どちらも見えなくしますが、`display: none`（Tailwind の `hidden`）は **場所ごと消え**、`visibility: hidden`（`invisible`）は **場所を残したまま透明** になります。どちらも、押せず・Tab で止まらず・読み上げからも外れます。
月のラベルは `visibility: hidden` で隠しています。隠している間も箱の大きさが決まったままなので、見せたフレームですぐ正しい位置（中心合わせ）になり、そのままフォーカスを移せるためです（[`lib/monthLabels.ts`](../lib/monthLabels.ts) の `placeMonthLabel`）。見えない要素にはフォーカスを移せないので、「見せてからフォーカスする」順番が大事です。

### 重なりの順番（スタッキングコンテキスト）と has-[:focus-visible]

位置を決めた要素（`absolute` や `fixed`）は、`z-index` の大きいものほど手前に描かれます。ただし比べられるのは **同じ「重なりの単位」（スタッキングコンテキスト）の中** だけです。`isolation: isolate`（Tailwind の `isolate`）はその単位を新しく作ります。
このサイトでは、UI の層を `isolate` にして、月のラベルの層をその中の一番下（`-z-10`）に置いています。キャンバスより手前、タブ・見出し・カード・操作パネルより奥になります（[`PortfolioExperience`](../components/PortfolioExperience.tsx)）。
ラベルの層は `fixed` にしています。UI の層が低い画面でスクロールしても、キャンバスと同じく動かないので、ラベルが石からずれません。

`has-[:focus-visible]:z-10` は、CSS の `:has()` で「中にキーボードのフォーカスがある間だけ」手前に出す指定です。操作パネルの下に隠れたラベルにフォーカスしても、今いる場所が見えます（[`MonthLabels`](../components/ui/MonthLabels.tsx)）。

### sticky と scroll-padding

`position: sticky` は、スクロールしても **スクロールする箱の上の端に張り付く** 指定です。解説カードのシートでは、× ボタンのある見出しの行を張り付けています。
張り付いた行の下に、キーボードで移った先のボタンが隠れないよう、スクロールする箱に `scroll-padding-top`（Tailwind の `scroll-pt-*`）で行の高さぶんの余白を取ります（WCAG 2.4.11）。スクロールする箱がカードでなくなる低い画面（`tiny:`）では、張り付けをやめています。

### WCAG（ウェブのアクセシビリティの基準）

W3C が定める、障害のある人も使えるウェブにするための基準。コメントに出てくる番号は達成基準です。

- **2.4.3**：フォーカスの順番が意味の通る順になっている（消えた部品から `<body>` に落とさない）。
- **2.4.7 / 2.4.11**：フォーカスの位置が見え、ほかの部品に隠れない。
- **2.5.3**：見えている文字が、読み上げの名前の先頭に入っている（音声で「JAN」と言えば押せる）。
- **2.5.7**：ドラッグでしかできない操作には、ボタンなどの代わりの手段がある。THE JEWELS の視点の回転（ドラッグ）とピンチの拡大には、代わりのボタンを置いていない（解説カードの視点を回すボタンは、2026-10-02 にユーザーの判断でなくした。石と月の選択はボタンでできる）。
- **2.5.8**：押せる的は 24 × 24px 以上。
- **1.4.3**：文字と背景のコントラストは 4.5:1 以上（大きい文字は 3:1）。

### ref の後始末（React 19）

`ref={(element) => { ... }}` のように関数で ref を受け取ると、要素ができたときに呼ばれます。React 19 では、その関数から **後始末の関数を返せる** ようになり、要素が消えるときに呼ばれます。
月のラベルでは、要素を入れ物に入れ、後始末で null に戻しています（[`MonthLabels`](../components/ui/MonthLabels.tsx)）。

### prefers-reduced-motion（動きを減らす設定）

OS の **「視差効果を減らす／動きを減らす」設定** を、Web ページから読み取るための仕組み（メディアクエリ）。
画面の大きな動きで酔いやすい人などが有効にしています。THE JEWELS では有効なとき、カメラが飛ばずにその場で切り替わり、選んだ石も回さず、解説カードのシートに合わせて描く範囲をずらすときもすぐに切り替えます。動きではない、ほかの石を薄くする変化（約 0.8 秒）と、指を乗せた石の小さな浮き上がりは止めません（[`usePrefersReducedMotion`](../lib/usePrefersReducedMotion.ts)）。

## 2. 3D の基本用語（Three.js / WebGL）

### キャンバス（canvas）

HTML の `<canvas>` 要素。**「絵を描くための四角い画用紙」**。
このサイトでは React Three Fiber の `<Canvas>` がその画用紙を用意し、その上に 3D が描かれます。
なお、テクスチャ生成（[`textures.ts`](../lib/textures.ts)）では、別の小さな 2D キャンバスに丸いグラデーションを描いて“光の粒”の画像を作っています。

### シーン（scene）

**「3D の世界そのもの・舞台」**。
太陽・海・宝石など、画面に映る物（メッシュ）やライトを **まとめて入れておく“箱”** です。カメラはこのシーンを覗き込みます。
このプロジェクトでは Sun / Ocean / Jewels の 3 つのシーンをタブで切り替えます。

### カメラ（camera）

**「その世界をどこから・どんなレンズで見るか」** を決める視点。
`PerspectiveCamera`（透視投影カメラ）は人間の目に近い見え方で、遠くの物ほど小さく見えます。

- `fov`（画角）：レンズの広さ。大きいほど広角。three.js では **縦方向** の角度で、横にどこまで見えるかは画面の縦横比で決まります。そのためスマホの縦長の画面では横が狭くなります。THE JEWELS では縦長のときだけ縦の画角を広げ、横に見える範囲を保っています（[`lib/scenes/jewels.ts`](../lib/scenes/jewels.ts) の `fitFov`）。
- **レンズシフト**（`setViewOffset`）：カメラの向きは変えずに、写る範囲だけを上下左右にずらす仕組み。「大きな写真の一部を切り取る窓」を動かすイメージです。THE JEWELS では、スマホで解説カードのシートが開いている間、石がシートに隠れないよう写る範囲を上へずらしています（`focusViewShift`）。
- `near` / `far`：映す距離の範囲。これより近い／遠い物は描かれません。
- `position`：カメラの置き場所。
- `lookAt`：カメラが向く先（注視点）。海シーンではこれを動かして“見回し”を表現しています。

### 画面の座標への投影（project）

3D の点が、画面のどこ（左から何 px・上から何 px）に写るかを求める計算。カメラから見た位置に直し（ビュー行列）、遠近をつけて -1〜1 の範囲に縮め（射影行列と w での割り算）、最後に画面の大きさを掛けます。
カメラの後ろの点は、計算すると上下左右が裏返って画面の中に来てしまうので、先に外す必要があります。

このサイトでは、月のラベル（HTML のボタン）を 3D の石のそばに置くのに使っています（[`lib/scenes/jewelLabels.ts`](../lib/scenes/jewelLabels.ts) の `projectToScreen`）。

### レンダラー（renderer）

**「シーンとカメラから、実際にキャンバスへ絵を焼き付ける装置」**（`WebGLRenderer`）。
GPU を使って毎フレーム描画します。`gl.domElement` が実際の `<canvas>` です。

### メッシュ（mesh）

**「形（ジオメトリ）＋見た目（マテリアル）＝実際に見える 3D の物体」**。
`new THREE.Mesh(geometry, material)` のように、形と質感を組み合わせて 1 つの物体になります。

### ジオメトリ（geometry）

**「物体の“形”＝頂点の集まり」**。
球（`SphereGeometry`）・平面（`PlaneGeometry`）などがあります。宝石シーン（THE JEWELS）では、Blender の JewelCraft で作った 12 石の形を [`public/jewels/jewels.glb`](../public/jewels/jewels.glb) に書き出し、drei の `useGLTF` で読み込んで使っています（取り出すのは [`lib/scenes/jewels.ts`](../lib/scenes/jewels.ts) の `pickStoneGeometries`）。

### マテリアル（material）

**「物体の“質感・見た目”＝どう光るか、何色か」**。

- `MeshStandardMaterial` / `MeshPhysicalMaterial`：物理ベースの標準的な質感（ざらつき・金属感・透明感など）。
- `ShaderMaterial`：**自分で書いたシェーダー**で見た目を完全に自作するマテリアル。太陽・海・切子の宝石はこれです。

### 頂点（vertex）と法線（normal）

- **頂点**：形を作る“点”。三角形の角。
- **法線（normal）**：面が**どちらを向いているか**を表す矢印。光の当たり方（明るさ）の計算に使います。

### バッファ属性（BufferAttribute）/ 属性（attribute）

**「たくさんの頂点データを、GPU に一気に渡すための一列の数字の並び」**。
位置・色・不透明度などを `Float32Array`（軽い数値配列）に詰めて GPU へ送ります。炎の帯はこの配列を毎フレーム書き換えて形を変えています。

### スプライト（sprite）

**「常にカメラの方を向く板」**。
光のにじみ・きらめきなど、平べったい光の表現に使います（向きを気にせず“光の粒”を置ける）。

### DPR（device pixel ratio）

**「画面の細かさ（Retina かどうか）の倍率」**。
高いほど綺麗ですが重くなるため、`dpr={[1, 1.6]}` のように上限を決めて負荷を抑えます。

## 3. シェーダー（見た目を計算するプログラム）

### シェーダー（shader）/ GLSL

**「GPU 上で動く、色や形を計算する小さなプログラム」**。言語は GLSL。
このサイトの“それっぽい”表現（燃える太陽・波・きらめく宝石）は、ほぼこのシェーダーが作っています。

- **頂点シェーダー（vertexShader）**：頂点を **どこに置くか**（形を動かす）。波の上下動などはここ。
- **フラグメントシェーダー（fragmentShader）**：ピクセルを **何色にするか**（見た目を塗る）。炎の色や水の反射はここ。

### uniform（ユニフォーム）

**「JS 側からシェーダーへ毎フレーム渡す“共通の値”」**。
`uTime`（時間）、`uBright`（明るさ）など。スライダーを動かすと、この uniform が更新されて見た目が変わります。
「全ピクセル共通で使う設定値」なので **uni**form（＝一様）と呼びます。

### ノイズ（noise）/ fbm

- **ノイズ**：**自然でなめらかなランダム模様**を作る関数（`snoise`）。雲・炎・波などの“ゆらぎ”の素。
- **fbm（fractal Brownian motion）**：ノイズを **周波数を変えて何枚も重ねた**もの。より複雑で自然な模様になります。
- 共有コードは [`shaders.ts`](../lib/shaders.ts) の `NOISE` にまとまっています。

### トーン / トーンマップ（tonemap）

**「明るすぎる色を、画面で表示できる範囲へ“いい感じに”圧縮する処理」**。
太陽のように非常に明るいものは、そのままだと真っ白に潰れて（白飛びして）しまいます。
トーンマップ（このサイトでは映画で使われる ACES 風のカーブ）を通すと、**明るい部分の階調を残しつつ自然な明るさ**に整えられます。
[`SunScene`](../lib/scenes/sun.ts) のフラグメントシェーダー末尾で `col=clamp((col*(2.51*col+0.03))/...)` としているのがそれです。
なお、`<Canvas linear flat>` の `flat` は **「R3F 側の自動トーンマップを切る」** 指定で、色をシェーダー側で完全に制御するためです（`linear` は色空間の自動変換なし）。
ただし THE JEWELS だけは、表示している間 three.js の **Neutral トーンマッピング**と sRGB 出力に切り替えます（[`JewelsScene`](../components/scenes/JewelsScene.tsx) の `useStudioLook`。下の「5. 宝石シーンで使う言葉」を参照）。

### フレネル（Fresnel）

**「浅い角度から見た面ほど強く光る／反射する」** という現象。
水面のふち、宝石の縁、太陽のリムが明るく縁取られるのはこれです。「視線と面の角度」で強さを計算します。

### 加算合成（AdditiveBlending）

**「重ねるほど明るくなる混ぜ方」**。
光・炎・きらめきなど **発光する表現**に使います（絵の具ではなく“光”を足すイメージ）。

### 深度（depth）: depthTest / depthWrite

**「手前・奥の前後関係」の管理**。

- `depthTest`：奥にある物を手前の物で隠す判定。
- `depthWrite`：自分の奥行きを記録するか。光のエフェクトは他を隠したくないので `depthWrite:false` にします。

### smoothstep / damp（なめらかに補う計算）

- **`smoothstep(下端, 上端, x)`**（GLSL の引数の順）：x が下端以下なら 0、上端以上なら 1、その間を **S 字のなめらかな曲線**でつなぐ。境目をくっきりさせたくないときに使います（太陽・浜辺のシェーダーに多く出てきます）。下端を上端より大きくすると、1 → 0 へ反転します（例: `smoothstep(0.78, 0.45, day)`）。three.js の `MathUtils.smoothstep` は x が先頭（`smoothstep(x, 下端, 上端)`）なので注意。
- **`damp(今, 目標, 速さ, 経過秒数)`**（three.js の `MathUtils.damp`）：毎フレーム、目標へ「残りの何割か」ずつ近づける。フレームの速さ（fps）が変わっても、同じ時間で同じだけ近づきます。
  THE JEWELS では、石の回転・浮き上がり・薄くする不透明度・描く範囲のずらしに使っています。

### 不透明度（opacity）と transparent

- **`opacity`**：マテリアルの不透明度（1 = 不透明、0 = 見えない）。**`transparent: true`** にしないと、three.js は不透明な物として描き、値を下げても薄くなりません。
  THE JEWELS では、石を選んでいる間、ほかの石の不透明度を 0.15 まで下げて、真っ白な背景へ溶かすように薄くしています（[`applyStoneOpacity`](../lib/scenes/jewels.ts)）。
  色を暗くする方法もありますが、白い背景の上では黒い影のように目立つのでやめました。

### 環境マップの強さ（光量スライダー）と白い床

- **環境マップの強さ**：映り込みや屈折で拾う、まわりの景色（下の「HDR」）の明るさの倍率。three.js の標準のマテリアルでは `envMapIntensity`（パールで使用）。
  drei の `MeshRefractionMaterial` には強さの設定が無く、色を「`color` × 環境マップから拾った光」で出すので、THE JEWELS では石の色に倍率を掛けています（[`refractionColor`](../lib/scenes/jewels.ts)）。縁の白い光（`fresnel`）は色とは別に白を混ぜるので、倍率には左右されません。
- **露出との違い**：露出（下の「トーンマッピングと露出」）は画面全体の明るさで、屈折の石では、縁の白い光（`fresnel`。露出には左右されるが、倍率には左右されない）を除けば、倍率と同じ見た目になります。ただし、どちらも**黒に掛けても黒のまま**なので、まわりの景色が暗いところは、どちらを上げても明るくなりません。
- **白い床**：2026-10-02 まで、環境マップの下半分（床）はほぼ黒（明るさ 0.01〜0.025）で、石の中で反射して下へ抜ける光線が黒を拾い、ダイヤのテーブル面の中心などが紺色に沈んでいました。そこで Blender のスタジオの床と壁を白くして焼き直しました（[`blender/build_jewels.py`](../blender/build_jewels.py) の `WORLD_GRADIENT`）。
- **`varying`**：頂点シェーダーで計算した値（面の向きや uv など）を、フラグメントシェーダー（ピクセルごとの計算）へ渡すための変数。頂点の間はなめらかに補われます。
- **描く順番（`renderOrder`）**：半透明の物は、不透明な物のあとに、カメラから遠い順に描かれます。`renderOrder`（小さいほど先）で順番を固定できます。
  THE JEWELS では、石の下の影を `-1`（最初）にして、薄くした石の向こうの影が視点によって透けたり隠れたりしないようにしています。太陽の光の輪（`lib/scenes/sun.ts` の `halo.renderOrder = 3`）も、`renderOrder` で順番を固定する点は同じです（こちらは最後に描くため 3）。

### レイヤー（Layers）

three.js の物（`Object3D`）は 32 個の **レイヤー**のどれに載るかを持ち、カメラや raycaster（押した物を探す光線）は、自分が見るレイヤーに載った物だけを扱います。
THE JEWELS では、影を落とさない石（薄くした石と、不透明へ戻りきっていない石）をレイヤー 1 へ移しています。画面を撮るカメラと raycaster はレイヤー 1 も見るので、石は描かれ、押して選べます。
一方、石の下の影（drei の `ContactShadows`）を撮るカメラはレイヤー 0 しか見ないので、薄くした石は影を落としません（薄い石の下に濃い影だけが残らないように）。
選択を外して石が戻るときは、不透明度が 0.9 以上になってからレイヤー 0 へ戻し、まだ薄い石の下に濃い影が先に出ないようにしています。

## 5. 宝石シーン（THE JEWELS）で使う言葉

### glTF / .glb

**「3D の形を、アプリの間で受け渡すための標準のファイル形式」**（“3D の JPEG” とも呼ばれます）。
`.glb` はその 1 ファイルにまとめたバイナリ版です。Blender で作った 12 石の形を [`public/jewels/jewels.glb`](../public/jewels/jewels.glb) に書き出し、drei の `useGLTF` で読み込んでいます。
ノード（オブジェクト）の名前を石の id（`garnet` など）にしてあるので、`nodes.garnet.geometry` のように名前で形を取り出せます。

### Blender / JewelCraft / BlenderMCP

- **Blender**：無料の 3D ソフト。形を作る（モデリング）、光を計算して絵を描く（レンダリング）ことができます。
- **JewelCraft**：Blender のアドオン（追加機能）で、ラウンド・オーバル・ペアシェイプなど、実物どおりのカットの宝石を作れます。
- **BlenderMCP**：AI（Claude Code など）が、動いている Blender に Python のコードを送って操作するための仕組み（MCP = Model Context Protocol）。
  このプロジェクトでは、実行したコードを [`blender/`](../blender/) にスクリプトとして残し、同じ結果を何度でも作り直せるようにしています。

### Cycles（パストレーシング）

Blender に入っている、**「カメラから光の経路を 1 本ずつ追いかけて、反射・屈折を物理的に計算する」** レンダラー（パストレーシング／レイトレーシングの一種）。
宝石の中で光が何度も反射して生まれる輝きを、本物に近く描けます。その代わり 1 枚に数秒〜十数秒かかるので、リアルタイムには使えません。
THE JEWELS では、Cycles でスタジオの照明を 1 枚の環境マップ（下の「HDR」）に焼き、Web のリアルタイムの石がそれを映り込みに使っています（最初の版では、回転の連番写真も Cycles で描いて見せていましたが、2026-09-30 にやめました）。

### HDR / 正距円筒図法（equirectangular）の環境マップ

- **HDR**：1.0（白）を超える明るさもそのまま記録できる画像。光源の強さ（ここでは 80 など）を残せるので、映り込みや屈折がリアルになります。
- **正距円筒図法**：まわり 360° の景色を、世界地図のように 1 枚の横長の画像（横 = 方位 360°、縦 = 上下 180°）に広げたもの。
  THE JEWELS では、Cycles のスタジオを石の位置から全方向に見た画像を [`public/jewels/studio.hdr`](../public/jewels/studio.hdr) に焼き、Web の屈折の計算に使っています（[`blender/render_env.py`](../blender/render_env.py)）。

### 背景（scene.background）と ContactShadows

- **`scene.background`**：シーンの背景。色・画像・HDR を入れられます。THE JEWELS では、商品写真の **白ホリ**（継ぎ目の無い白い背景）のように真っ白な色を入れ、石だけが浮かぶ空間にしています。
  R3F では `<color attach="background" args={["#ffffff"]} />` と書くと `scene.background` に入り、シーンを離れるときに R3F が元の背景へ戻します。色の背景はトーンマッピングを通らず、環境マップとも関係が無いので、光量スライダーを動かしても白のままです。
- **`ContactShadows`**（drei）：基準面（高さ 0）の真下から上を向いたカメラで物の形を撮り、ぼかして、基準面に置く板へ貼る「やわらかい接地の影」。ライトの影の計算を使わないので軽く、白い背景で石が宙に浮いていることを伝えます。
  drei は影の画像をぼかすとき、ぼかし用の板を原点に置いたまま影用のカメラで撮るので、`position` で上へずらすと、その板がカメラの後ろに回り、影が出なくなります（2026-10-02 に、0.02 mm 上げていて影が出ていなかったことがわかった）。THE JEWELS では 0.01 mm 下げています。
  また、drei 10.7.7 の `ContactShadows` は、作った描画先（512 × 512 の画像 2 枚）やマテリアルを、消えるときに片付けません（誕生石のタブを開き直すたびに GPU のメモリが少しずつ残る。既知の制約）。
- **`scene.environment` の落とし穴**：three.js（r185）は、`envMap` を持たない標準のマテリアルの映り込みの強さを `scene.environmentIntensity` で**上書き**し、マテリアルごとの `envMapIntensity` を無視します。
  そのため THE JEWELS では `scene.environment` を使わず、パールに `envMap` を直接渡しています。

### 屈折率（IOR）と全反射

- **屈折率**：光が物に入るときに、どれだけ曲がるかの強さ。空気は 1.0、水は 1.33、ダイヤは 2.42。大きいほど光が大きく曲がります。
- **全反射**：屈折率の大きい物の中から外へ出ようとした光が、浅い角度だと外に出られず、表面で 100% 跳ね返る現象。
  ダイヤの下側（パビリオン）の角度は、入った光が全反射して上へ戻ってくるように決められていて、これが「輝き」の正体です。

### 分散（ファイア）

**「屈折率が光の色（波長）ごとに少しずつ違うため、白い光が虹色に分かれる」** 現象。宝石の虹色のきらめきを「ファイア」と呼びます。
宝石学では、赤と青の光の屈折率の差（B–G 間）で表し、ダイヤは 0.044、アメジストは 0.013 です（[`lib/birthstones.json`](../lib/birthstones.json) の `dispersion`）。
Blender 5.2 のガラスには分散の設定が無いので、赤・緑・青だけを通すガラスを 3 つ重ね、色ごとに屈折率をずらして表しています。
Web（MeshRefractionMaterial）では、赤を「屈折率 × (1 − 値)」、青を「屈折率 × (1 + 値)」で 3 回光線を追いかけ、その差が「石の分散 × 分散スライダー × `FIRE_GAIN`（4）」になる値を渡しています（[`lib/scenes/jewels.ts`](../lib/scenes/jewels.ts) の `aberrationFor`）。
実物のままの差では画面の上で虹色がほとんど見えないので、スライダーで強めて見せます。速い近似（`fastChroma`）は光線の向きを決まった方向へ少しずらすだけで、屈折率の違いによる色の広がりにならないため、使っていません（drei の初期値は true なので、`fastChroma={false}` をはっきり渡しています）。

### 吸収（ボリューム）

**「光が石の中を進むほど、特定の色が吸い取られていく」** 性質。ルビーは赤以外が吸われるので、厚いところほど深い赤になります。
Cycles では「Volume Absorption（吸収ボリューム）」で表します。Web の屈折の計算ではこれを再現できないので、色を累乗して濃くすることで近づけています（[`lib/scenes/jewels.ts`](../lib/scenes/jewels.ts) の `tintFromColor`）。

### 薄膜干渉（パールの照り・iridescence）

**「ごく薄い膜の表と裏で反射した光が重なり、見る角度によって虹色に見える」** 現象。シャボン玉や油膜の虹色と同じです。
真珠は薄い真珠層が何百、何千と重なっているので、表面に虹色の照り（オリエント）が浮かびます。three.js では `MeshPhysicalMaterial` の `iridescence`、Blender では Principled BSDF の Thin Film で表します。

### MeshRefractionMaterial と BVH

- **MeshRefractionMaterial**：drei に入っている、宝石向けのマテリアル（シェーダー）。画素ごとに光線を石の中へ曲げて進め、中での反射を何回か追いかけてから、出ていく向きの環境マップの色を拾います。
- **BVH**（Bounding Volume Hierarchy）：形の三角形を「入れ子の箱」に分けて整理した木構造。光線がどの三角形に当たるかを、全部の三角形を調べずに素早く探せます。
  MeshRefractionMaterial はこれを GPU のテクスチャとして持つので、使い終わったら片付けが必要です（[`lib/scenes/jewels.ts`](../lib/scenes/jewels.ts) の `disposeRefractionBvh`）。

### CameraControls（方位角・極角）

drei に入っている、カメラの操作（ドラッグで回す・ホイールで寄る）と、**なめらかな移動**（`setLookAt` / `rotateTo`）ができる部品。月を選んだときにカメラが石へ回り込むのに使っています。
向きは「方位角」（水平方向にどれだけ回ったか）と「極角」（真上からどれだけ傾いたか）で表します。
方位角は回した分だけ増え続ける（2 周すると 4π になる）ので、そのまま目標を渡すと逆回りに何周もすることがあります。`nearestAngle` で、同じ向きのうち今の角度に一番近い値を選んで渡しています。

### トーンマッピング（AgX / Neutral）と露出

- **露出**：写真の明るさ（シャッター速度や絞りに当たる）。three.js では `toneMappingExposure`、Blender では Exposure（+1 で 2 倍）。THE JEWELS では 2 倍（+1 段）に固定しています（光量スライダーは露出ではなく、上の「環境マップの強さ」を変えます）。
- **AgX**：Blender の標準の色変換。明るい部分を自然に白へ寄せます。Cycles で描くときに使っています。
- **Neutral**（Khronos PBR Neutral）：商品写真向けに、明るい部分でも **色相と彩度を保ちやすい** トーンマッピング。Web の THE JEWELS で使っています（AgX だと、屈折で強く光るルビーが桃色に褪せて見えたため）。

### Suspense とエラーバウンダリ

- **Suspense**：読み込みが終わるまで、その部分の表示を待たせる React の仕組み。`useGLTF` などは読み込み中に「待って」と知らせ、`<Suspense>` がそれを受け止めます。
- **エラーバウンダリ**：子の部品で起きたエラーを受け止め、画面全体が真っ白にならないよう、代わりの表示を出す部品（[`SceneErrorBoundary`](../components/SceneErrorBoundary.tsx)）。React 19 でもクラスでしか書けません。
  - このサイトには 2 段あります。3D のキャンバスの中は `SceneErrorBoundary` が、それ以外（UI の部品や、プログラムの読み込みの失敗）は Next.js の決まったファイル [`app/error.tsx`](../app/error.tsx) が受け止めます。`error.tsx` は Next.js が中でエラーバウンダリを用意してくれるので、関数で書けます。ただし同じ階層の `layout.tsx` で起きたエラーは受け止められません（それは `global-error.tsx` の役目で、このサイトでは置いていません）。
  - `error.tsx` が受け取る `unstable_retry` は「ページの中身を取り直して描き直す」関数です（Next.js 16.2 で加わり、`reset` より推奨）。名前の `unstable_` は「今後名前や動きが変わるかもしれない」という印です。
  - `error` に付く **`digest`** は、エラーごとに自動で作られるハッシュ（識別用の文字列）です。本番ではサーバーで起きたエラーの詳しい文言が画面側に届かない（秘密が漏れないようにするため）ので、代わりにこの番号でサーバーのログと照らし合わせます。

### チャンク（chunk）

ビルドのときに、プログラムを **小分けにした JavaScript のファイル**。必要になった部品のファイルだけを、あとから読み込めます。
このサイトでは `next/dynamic` で画面の本体（three.js を使う 3D と、その上の UI をまとめた `PortfolioExperience`）を別のチャンクに切り出しています（[警告とTODOの解説](./警告とTODOの解説.md) の「「4つ目の効果」：バンドルサイズ」の節）。
あとから読み込むので、**通信が切れるとそのチャンクだけ読めずにエラーになる** ことがあります。一度失敗した読み込みは覚えられていて描き直しでは直らないことがあるため、エラー画面に「ページを再読み込み」のボタンを置いています。

### Strict Mode（開発時の二度実行）

開発サーバー（`pnpm dev`）で React が有効にする点検の仕組み。**`useEffect` などをわざと 2 回実行して**、後始末（クリーンアップ）の書き忘れを見つけやすくします。
本番のビルドでは 1 回だけです。開発中に `console.error` が 2 回出ても、それだけなら不具合ではありません。

### dvh（動的なビューポートの高さ）

CSS の長さの単位。`100dvh` は **「いま実際に見えている画面の高さ」**（Tailwind では `h-dvh`）。
スマホではアドレスバーが出たり引っ込んだりして見える高さが変わりますが、`100vh`（`h-screen`）は変わらないため、画面の下端が隠れることがあります。`dvh` はその変化に合わせて高さが変わります。
